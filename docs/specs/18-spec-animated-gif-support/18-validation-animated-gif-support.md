## 5) Deviations from Spec

| #    | Deviation                                                                                                                                                                                                                                                                                                                                                     | Reason and impact                                                                                                                                                                                                                                                                                                                                            |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| i    | **One shared rgb444 palette across all frames** instead of per-frame quantization (spec Unit 2). `gifEncode.ts:20,86`; test `gifEncode.test.ts › encodeGif › shares one global palette across all frames`. The task doc (2.1) records this.                                                                                                                   | Per-frame rgb565 quantization took about 34 s for a 30-frame 128 px GIF, which breaks the auto-fit ladder (many encodes) and the "under 2 s" success metric. The shared palette encodes the same GIF in about 0.45 s at full quality. Cost: colour fidelity on GIFs whose frames use very different palettes is lower than per-frame quantization would give |
| ii   | **Extra decode limits**: a 256 M total-pixel budget (`GIF_MAX_TOTAL_PIXELS`, counted as screen area times frame count) and a frame-descriptor bounds check (`gifDecode.ts:9,156,162`).                                                                                                                                                                        | Stricter than the spec's caps: for example about 65 or more frames at 2048x2048 are rejected even though they are under 300 frames. The bounds check rejects GIFs whose frame rect leaves the logical screen instead of clipping them                                                                                                                        |
| iii  | **Only multi-frame GIFs switch single-image mode to multi-image mode.** A single-frame GIF stays a static image in single-image mode (`useGifImport.ts:57`, `App.tsx:85`).                                                                                                                                                                                    | Spec Open Question 2 says "uploading a GIF in single-image mode switches"; a one-frame GIF is treated as a normal static image per Unit 1, so switching would be a needless mode change                                                                                                                                                                      |
| iv   | **`item.canvas` is the poster / paused frame.** During playback the Konva node image is swapped directly and no React state changes (`useGifPlayback.ts:98`; `› swaps the node image on each tick without re-rendering`).                                                                                                                                     | Avoids a re-render per tick. Anything reading `item.canvas` while playing sees the poster frame; export and the scrubber go through the `animationRef` controls                                                                                                                                                                                              |
| v    | **Single-image export always renders the stage**, so a chosen background colour is included even with no stickers (previously only with stickers). UI nodes (transformers, crop overlay, brush cursor, selection outline) carry `name="ui"` and are hidden in every export (`exportComposition.ts:54`; `e2e › exports do not include the selection outline`). | Side effect of the single `exportComposition()` path. Behaviour change for single-image exports without stickers                                                                                                                                                                                                                                             |
| vi   | **Static crop now clamps to the image.** A rect hanging off an edge shrinks to the overlap; a rect that misses the image is a no-op (`frameOps.ts:28-62`; `MultiImageCanvas.test.tsx › crop confirm › positions a static crop at the clamped region`, `› is a no-op when the crop rect misses the item`).                                                     | Spec Unit 4 asked for this for animated items; it applies to static items too because they share the code path                                                                                                                                                                                                                                               |
| vii  | **`task typecheck` is a no-op repo-wide** (pre-existing: `tsconfig.json` has `files: []`). The real check, `npx tsc -p tsconfig.app.json --noEmit`, was run separately and passes.                                                                                                                                                                            | Not introduced by this branch. Worth fixing in the Taskfile separately                                                                                                                                                                                                                                                                                       |
| viii | **GIFs without a NETSCAPE loop block export as infinite loop**, following the spec wording ("infinite by default"). Browsers play such GIFs once (`gifDecode.test.ts › decodeGif › defaults the loop count to 0 when there is no NETSCAPE block`).                                                                                                            | The exported file may loop where the source played once                                                                                                                                                                                                                                                                                                      |
